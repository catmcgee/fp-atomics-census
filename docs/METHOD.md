# Method

## Pipeline

1. `scan-manifest.json` pins each repository to a commit. `make clone`
   fetches exactly those commits (depth 1). `scan.run` refuses to scan a
   checkout whose HEAD differs from the manifest unless told otherwise.
2. `scan/` finds candidate sites. For CUDA and C++ it combines a regex
   table (`scan/patterns.py`) with tree-sitter-cpp (`scan/cxx.py`) to drop
   matches in comments, strings and declarators, to name the enclosing
   function and its CUDA qualifiers, to collect the `if` conditions and
   early-return guards around the site, and to infer the operand dtype
   from casts, declarations or literals. Inline PTX is matched inside
   `asm` strings only. A second pass links call sites of small device
   helpers and macros that wrap a float atomic. For Python it parses the
   file with `ast` and records `tl.atomic_*` calls, the PyTorch operators
   from the taxonomy with their keyword arguments, CuTe DSL atomic
   helpers and PTX strings, and calls into opaque libraries.
3. `candidates/<engine>.jsonl` is the raw scanner output, committed as
   produced. `candidates/<engine>.coverage.json` records what was walked.
4. Every candidate in scope is read and either becomes a row in
   `inventory/<engine>.jsonl` or stays in `candidates/` with an
   `excluded_reason`. The checklist is `triage/CHECKLIST.md`; the schema
   is `triage/inventory.schema.json`. `triage/fill_snippets.py` copies
   the recorded line range verbatim from the checkout so no snippet is
   typed by hand, and `triage/validate.py` checks the schema, the sha,
   id uniqueness, snippet length and that the snippet is found at the
   recorded lines.
5. `allowlist/<engine>.md` is derived from the inventory: configurations
   that reach only A1, A2, A3-on-the-deterministic-side or B sites.
6. `inventory.csv` flattens every inventory row for spreadsheet use.

## What the scanner does not see

- Kernels generated at runtime: `torch.compile`/Inductor output,
  Triton autotune choices, JIT-generated CUDA from templates (DeepGEMM and
  FlashInfer JIT are scanned as templates, which is what matters).
- Binaries: cuBLAS/cuBLASLt, cuDNN, NCCL, NVSHMEM, TensorRT-LLM cubins.
  These are class C and listed with their call sites.
- Atomics reached through function pointers or dispatch tables that the
  wrapper pass does not follow. The wrapper pass only follows small
  device helpers and macros defined in the same repository.
- Contention. The scanner cannot tell whether two threads ever hit the
  same address; that is why every class-A sub-case is decided by reading.

## Known false-positive patterns and how they are handled

| pattern | handling | test |
|---|---|---|
| `atomicAdd` in a comment or string | kept as a candidate with `excluded_reason` | `test_comments_strings_and_dead_blocks_are_flagged` |
| code under `#if 0` | `excluded_reason: dead-block` | same |
| a function overloading a primitive name (`__device__ half atomicAdd(half*, half)`) | the declarator is excluded, the body's CAS loop is a site, the name is never used as a wrapper | `test_primitive_name_overload_is_a_site_but_not_a_wrapper` |
| `atomicMax` / `atomicMin` on floats through `__float_as_int` | class B hint, dtype float | `test_float_max_min_are_class_b` |
| integer counters and locks | class B hint from dtype | `test_integer_counters_are_class_b`, `test_lock_exch_cas_are_class_b` |
| identifiers that merely contain `atomic` | not matched | `test_name_collisions_not_reported` |
| host `std::atomic` | `excluded_reason: host` | `test_host_atomic_excluded` |
| PTX-looking text in a non-asm string | `excluded_reason: string` | covered by the comment/string test |
| macro wrappers | definition is the site; expansions are wrapper calls | `test_macro_wrapper_sites` |

## Coverage

Generated by `python -m triage.coverage_table candidates/*.coverage.json`
at the pinned shas. "In scope" means the directory is under a
`scan_paths` entry of the manifest and not excluded; directories that
are walked but out of scope are counted so that "no atomics found" is
never confused with "not scanned". Directories with no scanned files and
no candidates are omitted.
